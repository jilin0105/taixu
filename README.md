## 序：何为太墟

《列子·汤问》载：

> 渤海之东，不知几亿万里，有大壑焉，实惟无底之谷，其下无底，名曰归墟。八纮九野之水，天汉之流，莫不注之，而无增无减焉。

归墟者，众水所归之深渊。它既是万物归零之处，也是万物重新获得可能的地方。

**太墟**，正是你掌中的那道归墟。

它不是一个普通的聊天应用，也不只是披着界面的终端模拟器。它试图在 Android 受限的沙盒中开辟一方完整的 Linux 世界：让模型拥有语言，让工具拥有双手，让工作区成为记忆落地之处。

第一次启动时，那里尚且空无一物。RootFS 尚未展开，进程尚未苏醒，光标也没有闪烁。而当你初始化运行时、建立第一个工作区、向 Agent 交付第一项任务——一种微小的计算文明便由此开始。

> 于太墟中立极，于方寸间创世。

## 核心能力

### 深渊容器 · 无 Root 的 Linux

太墟以内置的 **PRoot** 为边界，在无需 Root 权限的情况下，于 Android 用户态运行 Debian Linux。这里拥有自己的 RootFS、包管理器、Shell 与目录体系。

它不是对宿主系统的越狱，而是在限制之中另立规则：边界仍在，世界由此成形。

### Harness · 让语言抵达现实

模型若只能回答，智能便仍停留在纸面。太墟的 Harness 将用户消息、模型推理、工具调用与结果回传串成一条循环，使 Agent 能够读取文件、执行命令、检查结果，并继续完成尚未结束的任务。

对话与工具记录会被持久化；思考过程、运行状态和中断也有明确归宿。语言不再只是语言，而成为行动发生之前的第一重形式。

### 工作区 · 立极

每一个项目都需要一处坐标。太墟允许创建和管理工作区，浏览目录、查看与编辑代码，并将 Agent 会话或终端关联到具体项目。

工作区不是世界的全部，却是世界开始变得可理解的原点：文件因路径获得位置，任务因上下文获得意义。

### 真实终端 · 字符即法则

太墟通过原生 PTY 与 Linux 会话提供交互式终端，处理输入、输出、ANSI 状态与进程生命周期。你可以绕过所有抽象，直接面对 Shell。

在这里，每一个字符都是命令，每一次回车都是因果的开端。

### 工具生态 · 为智能铸器

工具决定 Agent 能将意图推进多远。太墟提供工具注册、依赖解析、安装校验、日志脱敏与失败回滚机制，并已接入 Codex、Hermes、OpenClaw 等工具安装适配。

器物可以扩展能力，但能力必须伴随边界。安装与执行过程因此需要可观察、可停止、可验证。

### 仪表盘 · 观天

创造世界，也需要知晓世界如何运转。运行仪表盘展示 Linux 沙箱状态、内存、存储、架构、活跃任务与环境信息。

观测不是装饰。只有被看见的系统，才有可能被理解；只有被理解的能力，才值得被信任。

### 多模型连接 · 众水归墟

太墟支持 OpenAI 兼容接口，可配置不同的模型提供商、地址、模型与凭据。模型可以来自不同远方，但工作区、进程和执行边界仍留在你的设备之中。

本地并非拒绝连接，而是保留选择连接的权利。

## 架构概览

```text
┌──────────────────────────────────────────────┐
│                  Android 沙盒                 │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │           太墟运行时 · PRoot            │  │
│  │  ┌────────────── Debian RootFS ─────┐  │  │
│  │  │  Shell · PTY · 进程 · 包管理器    │  │  │
│  │  └──────────────────────────────────┘  │  │
│  └────────────────────────────────────────┘  │
│             ↑ 执行                ↑ 关联      │
│  ┌──────────────────┐   ┌─────────────────┐  │
│  │ Harness / Agent  │   │ 工作区 / 文件系统 │  │
│  │ 推理 · 工具调用   │   │ 浏览 · 编辑 · 项目 │  │
│  └──────────────────┘   └─────────────────┘  │
│             ↑ 对话                ↑ 操作      │
│  ┌────────────────────────────────────────┐  │
│  │ Compose UI · 仪表盘 · 终端 · 设置       │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

一项任务在太墟中的旅程：

```text
人的意图
   ↓
模型推理 → 选择工具 → Linux 执行 → 检查结果
   ↑                                  ↓
   └──────── 尚未完成则继续 ──────────┘
```

项目采用 Kotlin、Jetpack Compose 与多模块架构：

```text
app          应用入口、依赖装配与前台服务
core         模型、数据库、网络、设置与安全
runtime      PRoot、RootFS、Shell、PTY 与进程管理
tools        工具安装、依赖解析、校验与事务
harness      模型对话与工具调用循环
feature      首页、对话、终端、工作区、设置与导航
```

## 快速开始

### 环境

- Android Studio
- JDK 17
- Android SDK 37
- Android NDK `30.0.15729638`
- Android 10（API 29）或更高版本
- ARM64（`arm64-v8a`）设备

### 构建

当前仓库提供 PowerShell 脚本，用于下载、校验并提取 PRoot 所需的 ARM64 loader：

```powershell
.\tools\prepare-proot-runtime.ps1
.\gradlew.bat :app:assembleDebug
```

构建产物位于 `app/build/outputs/apk/debug/app-debug.apk`，也可以使用 Android Studio 直接部署到设备。

### 首次创世

1. 打开太墟，进入运行仪表盘。
2. 初始化 Debian 运行时，等待 RootFS 下载、展开并通过健康检查。
3. 在设置中配置模型服务、模型名称与 API Key。
4. 进入工作区，建立你的第一个项目。
5. 打开终端，敲下第一条命令：

```bash
uname -a
```

6. 进入 Agent 页面，描述目标，并观察语言如何一步步成为现实。

> API Key 是秘密，不应写入源码、提交记录或公开日志。请始终遵循最小权限原则。

## 哲学注脚

太墟不试图证明手机可以替代一切，也不假装有限的设备拥有无限的资源。

它只是提供一种选择：当你身处通勤的地铁、候机的长椅或深夜的床头，忽然想写一段代码、运行一个脚本、验证一个念头时，不必等待所谓「合适的地方」。

限制从未消失。但自由并不总是来自限制的消失，也可以来自我们在限制之中，仍能建立自己的秩序。

> 须弥纳于芥子，太墟纳于掌中。

如果你也相信「在限制中开辟自由」，欢迎加入太墟的建设：

```powershell
.\gradlew.bat test
.\gradlew.bat :app:assembleDebug
```
